# Sprint_7 — API-тесты сервиса «Яндекс Самокат»

Автотесты на API учебного сервиса [Яндекс Самокат](https://qa-scooter.praktikum-services.ru/).
Документация API: https://qa-scooter.praktikum-services.ru/docs/

## Структура

```
Sprint_7/
├── api/                         # слой клиентов API
│   ├── courier_api.py           # ручки курьера: создание, логин, удаление
│   └── order_api.py             # ручки заказа: создание, список, отмена
├── tests/
│   ├── test_create_courier.py   # «Создать курьера»
│   ├── test_courier_login.py    # «Логин курьера»
│   ├── test_create_order.py     # «Создать заказ»
│   └── test_order_list.py       # «Список заказов»
├── conftest.py                  # фикстуры-фабрики с очисткой тестовых данных
├── data.py                      # ожидаемые ответы и наборы для параметризации
├── helpers.py                   # генерация тестовых данных
├── urls.py                      # адреса ручек
└── pytest.ini                   # настройки pytest и Allure
```

## Запуск

Требуется Python 3.10+.

```bash
python -m venv .venv
source .venv/Scripts/activate     # Windows (Git Bash)
pip install -r requirements.txt
pytest
```

## Allure-отчёт

Результаты прогона пишутся в `allure-results` — это настроено в `pytest.ini`.

```bash
allure generate allure-results -o allure-report --clean
allure open allure-report
```

Быстрый просмотр без сохранения: `allure serve allure-results`.

## Что покрыто

**Создать курьера**

- курьера можно создать: код `201`, тело `{"ok": true}`;
- нельзя создать двух курьеров с одинаковым логином: код `409`;
- без обязательного поля (`login`, `password`) — код `400` и текст ошибки.

**Логин курьера**

- курьер может авторизоваться: код `200`, в теле есть `id`;
- без обязательного поля `login` — код `400` и текст ошибки;
- неверный логин, неверный пароль, несуществующий курьер — код `404`.

**Создать заказ**

Параметризация по цвету: `BLACK`, `GREY`, оба цвета, без цвета.
Во всех случаях проверяются код `201` и наличие `track` в теле ответа.

**Список заказов**

- ответ `200`, в теле возвращается список `orders`;
- элементы списка содержат трек-номер.

## Изоляция тестов

Каждый тест сам готовит нужные данные через фикстуры-фабрики `courier_factory`
и `order_factory`. После теста созданные курьеры удаляются, а заказы отменяются,
поэтому тесты не влияют друг на друга и запускаются в любом порядке.

## Замечание по документации сервиса

В ходе тестирования обнаружены расхождения сервиса с документацией:

- поле `firstName` помечено обязательным, но курьер создаётся и без него — сервис
  возвращает `201` вместо `400`;
- запрос авторизации без поля `password` (или с пустым телом) не возвращает ответ —
  соединение уходит в таймаут вместо ошибки `400`.

Эти случаи сознательно не включены в автотесты, чтобы прогон отражал фактическое
поведение API и оставался стабильным. Дефекты зафиксированы здесь.
